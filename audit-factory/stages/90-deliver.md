# Stage 90 — Deliver, file and start the work

An audit is not done when it is sent. It is done when it is filed, the work is in Basecamp,
and the first agent task has started.

1. **File the package** in the Agent Audit Library (Drive folder `1WMWOgMTqQ4hSuUUcFKBD9lpO3YO4Afr9`)
   as `<topic>-audit-YYYY-MM-DD.pdf` plus `-evidence-ledger.json`, `-action-register.json`,
   `-gate.json`, `-review.json`, `-run.json` (models, tokens, cost per stage). List the folder
   to verify; a save receipt is not proof.
2. **Create the Basecamp to-dos:** `python -m factory20 basecamp audit.json --ledger ledger.json
   --out todos.json`, then post them as a to-do list named `Audit Execution — <subject>` in the
   client's project. Agent to-dos carry their own brief; human to-dos are only approvals,
   decisions, recordings and sign-ins. Name the executing agent or function on each.
3. **Deliver** on the existing thread for that client (Basecamp first; email with Operations
   copied when the person is not on Basecamp). Lead with the one decision they need to make.
   No agent receipt line on client-facing messages.
4. **Prepared by** on page 1 shows the preparer's name and face. A full 20-page audit for a US
   recipient also triggers the face-socks gift via love@localservicespotlight.com.
5. **Schedule the follow-up** (4 days for a normal audit) and start the first agent-executed
   action the same day.
6. **Record the run** — one line per stage with model, tokens and cost — so the next run is
   cheaper and the tier choice is evidence, not habit.
